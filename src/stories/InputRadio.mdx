# InputRadio

A single radio button with a label and an optional description. To offer a choice between several options, use the [InputRadioGroup](?path=/docs/forms-inputradiogroup--docs), which renders the radios for you.

## When to use it

Use a standalone radio button only when you need a custom layout that the InputRadioGroup can't provide. Radios that share a `name` form a group.

## How to use it

Bind `group` to the value of the checked radio, as with `bind:group` on a native radio. Other attributes, such as `name` and `value`, go on the input; `class` and `style` go on the wrapper. The `id` is generated unless you pass one. Invalid styles come from an ancestor with `aria-invalid="true"`, such as the InputRadioGroup's fieldset.

## Usage guidelines

- **Do** capitalize each item of the list
- **Do** list the items in a rational order
- **Do not** punctuate the end of every list item
- **Do not** mark required fields with asterisks

## Disabled

Disabled form fields can be confusing to users, so use them with caution. Use a disabled radio input only if you need to communicate to the user that an option that existed before is not available for choosing now. Consider not displaying the field at all or add an explanation why the field is disabled.

## Accessibility

### Best practices

#### Write clear and concise labels

The `label` prop passed to the RadioButtonGroup and the `options` prop's `label` property constitute the group's and the input's labels respectively. The labels should be clear and concise, and should not contain any formatted or semantic content (such as headings or lists).

The label acts as the input's accessible name, exposed to assistive technology as plain text. Using non-phrasing content in a label element is invalid HTML.
